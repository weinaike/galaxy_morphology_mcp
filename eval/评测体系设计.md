# 评测体系设计文档

> 2026-07-27 修改

## 0. 结论与当前决策

### 0.1 一句话结论

当前正式采用的 **rule-based reward 是 v8**。它较好地对齐了 VLM 对单条 `parent → child` 转移的 improvement / non-improvement 判断，但尚未充分验证同一 parent 下多个候选的完整质量排序。因此，GRPO 首阶段应保留 v8 连续分数，同时增加执行门控和保守的 reward shaping；训练后再用 on-policy 同-parent多候选重新验证和校准。

### 0.2 已对齐与未对齐

| 问题 | 当前证据 | 结论 |
|---|---|---|
| 单条 child 是否优于 parent | VLM 标注对齐：Val accuracy 90.1%，Test accuracy 89.2%，ROC AUC 0.9094 | 已较好验证 |
| 同一 parent 下 positive 是否高于 negative | E1–E6 诊断：half-tie pairwise accuracy 77.1%，strict accuracy 70.5% | 有效但仅属中等可信度 |
| 两个 accepted child 谁更好 | 当前 VLM 二值标注把二者都视为 positive | 未验证 |
| 两个 rejected child 谁更差 | 当前 VLM 二值标注把二者都视为 negative | 未验证 |
| RL 新策略分布上是否仍然可靠 | 现有候选与标签主要由 `gemini-3.1-pro-preview` pipeline 生成，而非待训练策略及其训练后版本 | 未验证，需 on-policy 复测 |
| delete 操作 | Test recall 约 0.29，执行评测 SSR 约 0.38 | 明显短板 |

### 0.3 GRPO 当前方案

不覆盖 v8 的历史定义，区分两层接口：

```python
raw_reward = compute_rl_reward(...)          # v8：固定评测标尺
reward = shape_grpo_reward(raw_reward, ...)  # GRPO：训练侧适配
```

首阶段采用保守 hybrid reward：

```python
if parse_failed or galfit_failed or timeout or invalid_params:
    reward = -1.0
else:
    binary = float(raw_reward > 0.0514)
    margin = clip((raw_reward - 0.0514) / scale, -1.0, 1.0)
    reward = binary + lambda_margin * margin
```

首阶段确定采用上述 hybrid 结构；`lambda_margin=0.2~0.3` 只是待验证的初始候选，不是已经校准的结论，`scale` 应由固定验证集的 IQR 或 MAD 确定。必须同时保存 `raw_reward`、`binary_reward`、`shaped_reward`，以及 bounds、chi² veto、解析失败、GALFIT 失败和超时等原因；否则 shaping 无法区分“硬失败得到 0”和“正常计算恰好得到 0”。

这样做是因为原评测函数与 GRPO 优化目标的语义不同：v8 中边界违规或 chi² 明显恶化会返回 0，但合法的轻微恶化动作可能得到负连续分数；若直接用于 GRPO，非法动作反而可能优于合法负分动作。训练侧需要显式失败惩罚和稳定尺度。

## 1. 三层评测体系

参考 AndroidControl-High，将评测拆为三个层次：

| 层次 | 回答的问题 | 是否执行 GALFIT | 核心指标 |
|---|---|---:|---|
| 离线评测 | 模型输出是否匹配参考 action | 否 | 格式、动作类型、参数、分层准确率 |
| 执行评测 | action 执行后是否真的改善 | 是 | GALFIT 成功率、SSR、分动作 SSR |
| SOP 半在线轨迹评测 | 多轮交互能否持续推进并停止 | 是，多轮 | 轨迹成功率、步数、失败位置、停止质量 |

三层不能相互替代：离线匹配不等于物理效果，单步执行改善不等于多轮任务成功，多轮指标也需要单步诊断定位问题。

## 2. Reward 建模的两条路线

### 2.0 数据约束与建模目标

**现有reward监督信息的分布。** 当前可规模化获得的标注产生于训练数据生成阶段。VLM reward 同时读取 parent/child 残差图、参数和拟合指标，输出转移标签：

```text
y(parent, child) = child 是否比 parent 更好
```

它能够较可靠地提供 `accepted > rejected`，却没有给出 accepted 内部或 rejected 内部的细粒度次序。在星系成分分解中，多组参数可能因简并性得到同样合理的拟合；即使由专家或当前最可信的 VLM judge 判断，稳定区分两个都改善的结果也很困难。因此，本阶段不把 `accepted_A > accepted_B` 视为可获得的监督，更不使用 χ²/BIC 的微小差值自动充当这类真值。

**reward建模目标。** 首先保留与现有 VLM 转移标签直接对齐、能够复现的正负判断；其次，在不夸大监督能力的前提下，为 GRPO 同一 parent 下的候选比较保留有限的连续信号；最后，通过失败门控、小权重 margin 和 on-policy 复测，限制未经标注验证的细粒度排序对策略更新的影响。

**可验证的边界。** 当前对reward能够验证的是单条转移的正负分类，以及同一 parent 下 `accepted > rejected` 的组内排序；不能验证 `accepted > accepted` 或 `rejected > rejected`。因此，GRPO alignment 不是证明 v8 已成为完整价值函数，而是确认它在现有可标注偏序上是否足以作为受约束的训练信号。具体指标与适配方式见第 4 节。

### 2.1 路线 A：建模绝对价值 `V(child)`

该路线只输入 child 的当前残差图、拟合参数和指标，输出当前状态的绝对质量：

```text
V(child) = f(current_residual, current_params, current_metrics)
```

优点是形式上适合比较任意两个 child，也可能为 accepted-accepted 提供排序。但它**不能直接与现有转移标签对齐**。现有标签表达的是：

```text
y(parent, child) = child 是否比 parent 更好
```

同一个 child 相对于较差 parent 可以是 improvement，相对于更好 parent 却可能是 degradation；此外，不同星系的绝对 BIC、χ² 和残差尺度也未必可直接比较。因此，不能用单个 child 的绝对分数直接拟合转移标签。

若未来选择绝对价值路线，需要新增以下一种监督：

1. 绝对终局质量或有序等级标注；
2. 同一任务内的可靠 pairwise 标注，并学习：

```text
P(child > parent) = sigmoid(V(child) - V(parent))
```

训练奖励仍应使用潜势差 `V(child)-V(parent)`，而不是裸 `V(child)`。

### 2.2 路线 B：建模相对改进 `R(parent, child)`

当前 v8 采用该路线：

```text
R(parent, child) = f(Δχ², ΔBIC, child_params, residual_quality)
```

它与 VLM reward 和现有标签语义一致，能够直接做二分类 alignment。对于同一个 parent，不同 child 共享基线，因此连续分数也可以启发式地用于候选排序。

但二值标签只能验证：

```text
accepted > rejected
```

不能验证：

```text
accepted_A > accepted_B
rejected_A > rejected_B
```

所以 v8 的连续数值具有启发式排序能力，但当前证据只验证了部分顺序，而不是完整质量排序。特别是当 `child_A` 和 `child_B` 都为 accepted 时，现有标签不能判断谁更好；受参数简并性和天文判断成本限制，这类标签在当前阶段难以可靠、规模化获取。这里的结论是“暂不监督该顺序”，而不是假定二者质量相同。

### 2.3 当前选择

保持路线 B 作为第一阶段 GRPO reward。暂不改成仅输入当前 child 的绝对价值模型，原因是现有标注天然属于 `child > parent` 分布；贸然移除 parent 信息会失去可验证的监督语义。

## 3. v8 如何复刻 VLM Reward

### 3.1 “复刻”的准确含义

v8 不是逐字翻译 VLM prompt，也不是完整复制 VLM 的视觉能力，而是尽可能复刻 `calculate_reward_model_with_param` 的最终判断行为：

| VLM 判断维度 | v8 代理量 |
|---|---|
| `param_plausible` | spec 初值和 GALFIT 拟合后参数边界 |
| χ²/χ²ν trend | `log10(old_chi2_nu/new_chi2_nu)` |
| metric consistency | BIC 改善及与 χ² 的联动门控 |
| residual improved | 残差噪声质量分支 |

当前 alignment 和执行评测调用没有传入 residual/sigma/mask，因此已有结果中的 `r_noise` 实际为 0。现有 90.1%/89.2% 主要来自参数边界、χ² 和 BIC；不能据此宣称已经复制了 VLM 的完整视觉判断。

### 3.2 v8 公式

```text
若 spec 或拟合后参数越界：
    raw_reward = 0
若 r_chi2 < -0.1：
    raw_reward = 0
否则：
    raw_reward = 10 × r_chi2
               + 0.5 × effective_r_bic
               + 5 × r_noise
```

其中：

```text
r_chi2 = log10(old_chi2_nu / new_chi2_nu)
r_bic  = sign(old_bic-new_bic) × log10(1+|old_bic-new_bic|)
```

BIC 正贡献上限为 2，并根据 parent χ²ν 启发式衰减：

| parent χ²ν | BIC 正贡献系数 |
|---|---:|
| `[0.9, 1.15]` | 0.3 |
| `[0.8, 0.9)` 或 `(1.15, 1.4]` | 0.5 |
| 其他 | 1.0 |

参数边界包括：`n∈[0.1,8]`、`Re∈[0.2,300]`、`q∈[0.05,1]`、`mag>0`，同时检查 action spec 和拟合结果。

### 3.3 版本结论

正式选择的是 **v8**：v7 基础上修复 expdisk fit-log 只有 4 个值、被旧 parser 静默遗漏的问题。

- v9 将 damping 外推到过拟合区，造成 FN 明显增加，作废。
- v10 把 VLM 文本中的示例数字实现成 redundancy/negligible-flux 硬规则，误伤严重，作废。
- 后续所谓“v11”没有形成新的 reward 公式，本质是回退到 v8，并以 Precision-first F1（precision floor=0.85）选择阈值。

因此统一表述为：**v8 raw reward + 锁定阈值 0.0514**。阈值选择策略不构成新的 reward 版本。

## 4. 从 VLM Alignment 到 GRPO Alignment

### 4.1 已完成的 VLM 二分类对齐

`eval/validate_reward_alignment.py` 按 `physical_id` 划分 val/test，在 val 上校准权重和阈值，并锁参评测 test。

| 数据集 | n | ROC AUC | Accuracy | Precision | Recall | F1 | FP | FN |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Val | 2773 | 0.9094 | 90.1% | 0.871 | 0.840 | 0.855 | 121 | 155 |
| Test | 1133 | — | 89.2% | 0.863 | 0.834 | 0.848 | 54 | 68 |

该结果验证的是“正负分离能力”：随机取一个 VLM positive 和一个 VLM negative 时，连续分数总体上有较强的排序能力；卡阈值后能较准确复现 VLM 的二值判断。

### 4.2 更贴近 GRPO 的同-parent评测

GRPO 在同一 prompt/state 下比较一组 rollout，因此更直接的指标是：

```text
P(raw_reward(positive) > raw_reward(negative) | same parent)
```

E1–E6 只读诊断结果：

| 统计 | 结果 |
|---|---:|
| mixed parents | 158 |
| positive-negative pairs | 645 |
| wins / ties / losses | 455 / 84 / 106 |
| strict accuracy | 70.5% |
| half-tie accuracy | 77.1% |

89.2% 与 77.1% 不属于同一口径：前者是在 E7_full test 上对单条 parent-child 转移卡阈值后的二分类 accuracy；后者是在 E1–E6 同-parent正负候选对上比较连续分数，且 tie 计半对。E7_full 每个 parent 最多只保留一个 child，不能直接计算同-parent pairwise，因此使用 E1–E6 并不表示 E7_full 测错。

从数量上看，E7_full test 的 positive recall 约为 0.834、negative specificity 约为 0.925，两者乘积约为 0.772。这只能说明“同时正确处理正、负候选比单样本分类更难”，不能把 77.1% 视为由 89.2% 数学推导出的结果，因为两项实验的数据分布和打分规则均不同。

该指标只比较 accepted 与 rejected，不要求区分 accepted-accepted 或 rejected-rejected。

### 4.3 为什么不直接把 reward 卡成 0/1

二值化会制造大量同-parent平局：

- 两个候选都超过阈值：`1 == 1`；
- 两个候选都低于阈值：`0 == 0`。

连续 v8 至少保留了候选间的 margin。严格单调的 `tanh` 或缩放不会改变 pairwise 排序；clip、分段门控和二值化可能增加 ties。GRPO 评测必须同时报告 raw、binary 和 shaped 三种分数，不能只看阈值 accuracy。

### 4.4 GRPO 首阶段必须做的对照

至少比较：

1. `Binary`：仅 `I(raw_v8 > 0.0514)`；
2. `Continuous`：连续 v8，经稳健归一化；
3. `Hybrid`：binary 加小权重 continuous margin；
4. `SFT baseline`：不做 RL。

训练期间监控 reward、KL、entropy、有效 rollout 比例、GALFIT 成功率和动作分布；训练后用 VLM accepted rate、SSR、同-parent pairwise、SOP 成功率以及 add/modify/delete 分项判断是否真实提升。

### 4.5 第一阶段 GRPO 的验收与分流

第一阶段的目标是验证 reward 在训练策略分布上是否仍然有效，而不是仅证明训练 loss 或平均 shaped reward 上升。与同一 SFT baseline、固定物理星系 test split 比较后，按以下证据分流：

| 观察结果 | 判断 | 下一步 |
|---|---|---|
| 独立 VLM accepted rate 改善，GALFIT 成功率满足预设非劣界限，且同-parent pairwise 与动作分项无灾难性退化 | reward 与任务目标基本一致 | 保留 checkpoint，完成 SOP 复核并扩大 on-policy 样本后进入第二阶段 |
| shaped/raw reward 上升，但 VLM accepted rate 或执行指标下降 | reward hacking 或分布外失效 | 停止续训，审查高分 rejected 样本并修改 shaping/rule |
| 整体提升但 delete 继续恶化 | 动作类型覆盖失衡 | 构造 delete 困难负例，做定向 SFT/DPO 或动作重采样 |
| 各候选 reward 大量相同、组内方差接近 0 | GRPO 缺少可学习排序信号 | 调整采样温度、候选数或 margin；不能只延长训练 |
| 与 SFT 差异不显著 | 当前数据不足以证明 RL 有增益 | 扩大固定测试集或报告置信区间后再决定 |

评测前需预先指定主指标和非劣界限：第一阶段以独立 VLM accepted rate 为主指标，GALFIT 成功率为执行安全门控；SSR 与训练 reward 同源，只作为诊断指标，不能单独证明 RL 有效；SOP 完成后再增加轨迹级主指标。所有“改善/退化”都应报告样本数和按 `physical_id` 聚类重采样的 bootstrap 置信区间，不能把同一星系的多步样本当作相互独立；预先固定的 test split 只做最终比较，shaping 超参数和停止规则只能使用 train/val 或独立开发集确定。

## 5. 训练链路：SFT、DPO 与 GRPO 的顺序

推荐主流程：

```text
SFT → 可靠同-parent偏好足够时先做 DPO → 保守 GRPO
                                           ↓
                              on-policy 多候选 + VLM 标注
                                           ↓
                               定向 DPO → 第二阶段 GRPO
```

- **SFT 必要**：先学会合法输出、基本操作和多轮接口。现有结果从 Base 的 GALFIT 成功率 0% 提升到 SFT 的 95.2%。
- **DPO 条件性必要**：仅使用经过执行和 VLM 判断的 same-parent `accepted > rejected`。弱模型输出不能自动视为负例。
- **GRPO 必要性取决于目标**：若要利用执行反馈并超过静态示范分布，需要 on-policy GRPO；若只做稳定模仿，SFT+DPO 可以作为终点。

首轮 GRPO 后不应盲目续训，而应固定 checkpoint，对每个 parent 采样多个候选，执行 GALFIT 并由 VLM 重标注。新数据用于检查分布漂移、reward hacking、动作类型偏差，并决定是否重标定 shaping、做定向 DPO 或进入第二阶段 GRPO。

## 6. 三层评测的详细定义

### 6.1 离线评测

入口：`eval/evaluate_sft.py`。

建议保留：

- 格式合法率与字段完整率；
- 动作类型准确率；
- add/delete 的 component_type；
- modify 的 component_index 和 parameter_name；
- 数值参数误差；
- 按对话深度与动作类型分层；
- 混淆矩阵和错误样本导出。

当前 A6000 `eval_sft_qlora` 结果：格式有效率 100%，动作类型准确率 77.14%；modify 90%，add 65.38%，delete 11.11%；depth=2 动作类型准确率 46.15%。离线结果说明格式和 modify 较好，delete 与深层对话仍是主要问题。

### 6.2 执行评测

入口：`eval/run_exec_eval.py`。

对模型 action 实际执行 GALFIT，并记录：

- action 是否解析成功；
- GALFIT 是否执行成功；
- parent/child χ²ν、BIC 和拟合参数；
- v8 raw reward 与锁定阈值后的 `rule_binary`；
- 分动作类型 SSR；
- 与参考 action 类型是否一致，作为诊断项而非 SSR 的组成部分。

当前 A6000 测试集：105 条中 GALFIT 成功 100 条，成功率 95.2%；SSR 60.0%；add 66.7%，modify 60.3%，delete 约 37.5%。

### 6.3 SOP 半在线轨迹评测

入口：`eval/run_sop_eval.py`，当前仍需补齐完整执行闭环。

建议指标：

- trajectory success rate；
- 每轨迹改善步比例与累计改善；
- 达到停止条件的步数；
- 首次失败位置；
- 无效动作、重复动作和振荡；
- 最大步数退出率；
- 按初始拟合难度和动作类型分层。

SOP 评测必须区分“中间某一步改善”和“整条轨迹成功”。

## 8. 已知能力边界与风险

1. 当前标签只覆盖 `child > parent` 的二值判断，不能证明完整排序质量。
2. v8 看不见 VLM 能利用的全部视觉结构、成分冗余和几何关系。
3. 当前 `r_noise` 在主要 alignment/执行结果中未实际启用。
4. delete 的 recall 和 SSR 明显低，需要定向数据与评测。
5. RL 会改变候选分布，历史 89%/77% 不能自动外推到新策略。
6. 连续 reward 可能被模型利用，必须监控 reward 上升而 VLM/执行效果下降的现象。
7. 绝对 χ²/BIC 不应跨星系直接解释为统一质量尺度。

## 9. 实施清单

### GRPO 前

- [ ] 冻结并标记 `compute_rl_reward` 为 v8 raw reward；
- [ ] 新增独立 `shape_grpo_reward`，不覆盖 v8；
- [ ] 在固定数据上复现 Val/Test alignment；
- [ ] 固化 E1–E6 same-parent pairwise 报告；
- [ ] 明确失败动作的负奖励与 reward scale；
- [ ] 准备 Binary / Continuous / Hybrid ablation。

### 第一阶段 GRPO 后

- [ ] 与 SFT baseline 在相同测试集做离线、执行和 SOP 对比；
- [ ] 生成 on-policy 同-parent多候选；
- [ ] 用 GALFIT + VLM 标注 accepted/rejected；
- [ ] 重测阈值分类、同-parent pairwise 和动作分项；
- [ ] 人工审查高 reward 但 VLM rejected 的样本；
- [ ] 根据结果选择定向 DPO、reward 重标定或第二阶段 GRPO。

## 10. 代码入口

| 文件 | 用途 |
|---|---|
